# Implementation decisions

## First increment

Persistent responsibilities are independent of execution sessions. Explicit bindings connect native session observations to units. A session roster is not automatically an organizational hierarchy.

The primary native page is a nested systems graph; compute allocation is a separate native page. Only observed activity animates. Empty and missing data remain empty or unknown. Host navigation, session opening, feature watches, authentication and public SDK storage are reused.

## Scope and verification

This increment establishes durable graph state, metadata-only observations and compute planning primitives. Planning is not dispatch. A qualified continuous regulator, autonomous adoption of improvements and migration of existing responsibilities are subsequent work, not implied by a working graph.

## Tooling

The repository was bootstrapped with Tool Factory; its native OpenClaw and npm surfaces were explicitly ejected before authored changes. A native feature contract is the operation authority. There is no duplicate MCP echo server or generic tool wrapper in the runtime.

## Skills

Frontend work follows Anthropic's official [frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design) guidance, subordinated to the host design system and graph-first brief. Abstraction review uses [abstraction-police](https://github.com/chris-metz/agent-skills/tree/main/skills/abstraction-police): unify shared intent, not coincidental shape. Third-party skill text is not redistributed.

## Projection ownership and transport

The backend projects explicit active run IDs separately from activity history. UI motion requires both a correlated start and an authoritative active identity; a new session cannot revive an old session's tool spinner. A service epoch excludes pre-start observations.

State mutations validate both live and restart-degraded public projections before CAS. The pinned SDK does not export its JSON-envelope validator, so a small version-specific preflight mirrors its documented runtime bounds and is tested through the real native feature wrapper. No private SDK imports are used. Allocation evaluation remains complete; only its explanatory diagnostics are paginated to fit the same envelope.

## Next integration boundary

Qualify the plugin in a disposable Gateway before live activation. Then connect trusted model/usage observers and an atomic reservation-to-native-execution owner, with receipt reconciliation and recovery tests. Only that verified execution path can support a continuous regulator. Rendering a graph or accepting an observation does not establish ownership of a responsibility.
